PCP Level 6 Module-Based Skills Radar — Implementation Report

HISTORICAL REPORT: this records the earlier accordion implementation. Its UI layout, component filename and test counts are superseded by MASTER_DETAIL_VERIFICATION_REPORT.md in this folder. The final UI uses ModuleMasterDetail.tsx with modules on the left and one question panel on the right. Original evidence below is retained for reference.

Branch and scope
Worked on the existing skills-radar branch. The working tree was clean at task start.
No commit, push, merge, rebase, reset or branch switch was performed.
The existing Programme Suitability/Modules implementation and other developers' steps were preserved.
No backend production files, database records, module configurations or migrations were changed.

Implemented result
Confirmed PCP L6 now shows selected-module accordions instead of the flat list. Other programmes retain the existing flat Skills Radar.
Each selected module displays its full published title, answered/assigned count, expand/collapse arrow and complete KSB rows.
Rows show code, type, exact full English description, existing rating/status and the existing Answer/Edit/View button. Long text wraps; mobile buttons can sit beneath it.
The existing Modal, nine rating choices/labels, high-rating note requirement, notes, evidence workflow, Cancel and Confirm & next were reused.
The open question is tracked by the existing profile ID rather than only a list index, protecting notes/evidence if module grouping changes while the popup is open.

Answer compatibility, progress and validation
The existing curriculum profile IDs are retained. Canonical wording replaces only the displayed title; no new answer IDs are generated.
Ratings, notes, evidenceFiles, existing action plans and historical assessment rows remain in the existing skillsRadar.assessments dictionary.
Regrouping changes only derived membership, never the saved answer envelope. Confirm & next follows the current assigned 71-question order.
Overall and per-module counts use the same answer IDs, count each KSB once, and ignore unrelated historical profile rows.
The existing answer persistence remains through the wizard's save/projection workflow. Merely opening/closing accordions does not call setSection or save APIs.
Missing/duplicate/ambiguous profile codes, missing or placeholder descriptions, unsupported selected module IDs or owner assignments produce configuration errors instead of bare-code fallback or silently losing KSBs.
A derived skillsRadar.configurationError blocks navigation/completion while PCP allocation is invalid, even if all returned profile items were rated. It is never saved as an answer. Other programmes' completion rules are unchanged.
Confirmed programme catalogue lookup is used even when board.programme.name is stale. Cached profile requests remain shared.

Database inspection
Used the existing Django connection under a read-only PostgreSQL transaction, following the installed Neon/Postgres skill guidance. No project, branch, connection string or database schema was created/changed.
Published module version 11 already contains the Strategic Risk mandatory module and PMO optional module required by the request. Allocation uses the actual pinned published snapshot, not seed module labels.
