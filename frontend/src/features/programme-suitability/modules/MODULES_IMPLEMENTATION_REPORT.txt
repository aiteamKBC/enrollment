Step 6 Programme Modules implementation
Date: 2026-11-01
Branch: CV-and-Programme-Suitability

Behaviour
- A single Programme Modules card renders below the existing assessment and
  Preview Assessment button, only after a submitted, confirmed selection.
- Its data comes from the confirmed selectedProgramme, including MM -> ME and
  PCP -> APM alternatives. It never substitutes the recommendation.
- ME, MM and APM display the supplied module titles and session counts without
  selection controls. PCP displays Operational, Strategic and Chartered cards,
  with one active pathway and individually selectable modules/submodules.
- PCP session counts are nullable in configuration and display an em dash.
  No authoritative programme module session counts were found in the inspected
  repository configuration/models; scheduled curriculum sessions are not used
  to invent programme module session counts. Credits remain visible.
- The three PCP cards sit side by side on desktop and stack on mobile. Chartered
  has a distinct purple border and the supplied APM recognition wording.
- Six-credit subtitles are displayed without adding a new credit-validation or
  wizard-completion requirement, as requested. No modules are auto-selected.
- Staff can review saved choices with disabled controls. Switching pathways
  retains earlier choices in storage but only the selected pathway is active.
- Preview Assessment remains the existing assessment-only modal.
- Existing automatic continuation to CV after programme confirmation is retained.
  The modules card is available when returning to the confirmed step. Navigation,
  assessment confirmation and scoring were not modified to hold the learner here.

Persistence
Uses the existing WizardContext setSection/saveIlr and Extended ILR API, not a
second learner/programme record or an assessment write after submission.
An optional draft.programmeModules field is stored inside the existing
enrolment."Extended_ILR"."Wizard_draft" JSON column:

  programme: PCP_L6
  pathway: operational | strategic | chartered
  modulesByPathway: map of pathway -> stable selected module identifiers

Choices autosave with a short debounce through the existing draft save function.
Module autosaves are serialized to keep slow earlier writes ahead of newer
choices. Failed saves keep the current selection and offer Retry. Hydration and
staff review do not trigger writes. Existing CV/other draft answers accompany
normal wizard saves and are retained. Existing drafts need no backfill.
No database migration, model change, new endpoint or production backend edit was
needed. The new backend test exercises the existing JSON round-trip boundary
with mocked storage; it does not write to a live learner database.
