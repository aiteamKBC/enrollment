Programme Suitability wizard-step relocation
Date: 2026-11-01
Branch: CV-and-Programme-Suitability

RESULT
The default apprenticeship wizard has 12 steps. Programme Suitability & Modules
is step 6, after Extended ILR; the existing CV/Job Description route is step 7.
The new stable slug is programme-suitability. Existing step slugs remain intact.
Modules functionality has not been implemented.

IMPLEMENTATION
ProgrammeSuitabilityStep renders the existing CvSuitabilityPanel without
duplicating or renaming its implementation. Its modal, scoring, recommendations,
selection restrictions, alternative reasons, account synchronization, result
card, preview and read-only answers are reused unchanged.

Assessment completion and programme confirmation now gate the new step. Next,
sidebar access, direct-route validation and final server submission use this
policy. Confirmation advances to the next visible configured step (CV by
default), independently of missing CV answers. Closing an unconfirmed result
keeps the assessment step incomplete. CV validation still runs when leaving CV.
The existing optional CV experience rule for enabled assessments is preserved.

CV renders its existing fields without an assessment panel or the obsolete
disabled/inert field wrapper. Its dynamic qualification label still reads the
globally loaded saved assessment pathway; its answer mapping is unchanged.

The existing assessment editor is hosted on the new step in the builder. An
enabled assessment step cannot be hidden. Enabling an assessment also makes
that step visible. Other step visibility controls are unchanged. Existing
disabled/unconfigured and already submitted/completed enrolment exemptions
remain as before. Hiding CV no longer bypasses the server assessment guard.

DATA AND CONFIGURATION
Old published layouts acquire the missing step during resolution/read, before
CV (or after Extended ILR if CV is absent), without changing their stored rows,
version numbers, assessment configuration, wording or answers. Repeated
resolution is idempotent. Existing saved step positions and custom questions
are retained. New publications recognize the stable slug as a built-in step.
There was no publication, learner update, assessment recreation or data rewrite
performed for this task. Confirmed saved assessments complete the new step
without a retake. No assessment API/model changes were needed.

No new migrations were created; no historical migrations were edited.
The built-in table registration only permits the existing builder mechanism to
create storage if an administrator later publishes custom fields on this step;
adding the empty step itself creates no table or columns.
