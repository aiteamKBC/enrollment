Chartered Pathway Module Hierarchy — Implementation Report

Root cause
The nested JSON relationship was already correct: certified-pmo had exactly four children; ai-project-management, portfolio and earned-value were root-level Chartered modules. This was verified against defaults, published wizard version 11 and the single existing private modules draft.
The learner table placed the group header, its children and later root modules in one tbody. Its rowgroup header therefore also scoped later independent modules. In addition, global table first-cell padding was 1.25rem, exactly the old pl-5 child padding, so children had no visible additional indentation.
No database/configuration correction was needed. Published data, private drafts, assessment snapshots and saved learner choices were not rewritten in this task.

Implementation
- ProgrammeModulesCard now scopes each root group to a separate tbody containing only its header and actual nested children. Consecutive root modules remain together outside that rowgroup.
- Only nested module labels get extra indentation and a subtle vertical guide. A subtle top divider and spacing separate the following independent root modules.
- Group detection uses explicit GROUP metadata or the existing structural fallback for old snapshots. Module titles/positions are not used to infer relationships.
- The existing Admin module editor exposes Parent group for actual modules where groups exist. None (pathway level) clears the parent; the choice uses stable group IDs and nested JSON, with no new database mapping or Admin page.
- Parent reassignment preserves all module settings and IDs, changes only the JSON location and destination display order, and keeps edits in the existing private Draft/Publish workflow.
- Fixed publication retention: moved module IDs are recognised throughout the same pathway, so moving a module does not reintroduce an inactive copy under its old parent. Truly omitted modules/groups are still retained as inactive. Historical configurations are never mutated.
- No credit, optional selection, assessment, programme recommendation, step completion or navigation logic changed. Other PCP pathways contain no groups, so their existing controls/rendering remain as before.
