PCP mandatory modules, optional rules and editable pathway notes
Date: 2026-11-01
Branch: CV-and-Programme-Suitability

Implemented
The original Operational, Strategic and Chartered notes are stored exactly as
provided in each pathway's existing description field. Admin labels this field
Pathway Note; no duplicate note field was introduced. Notes appear immediately
below the title, on selected and unselected cards, with wrapping mobile text.
Notes can be edited, blanked, privately saved, previewed and published using the
existing builder workflow. No ChPP guarantee or automatic accreditation was added.

Modules now support isMandatory. Pathways support
requiredOptionalModulesCount, alongside the existing targetCredits field.
Module order and display names do not determine mandatory status. Selectable
actual modules have a Yes/No Mandatory Module control. Parent headings do not.
Adding submodules converts their parent into an uncredited, nonselectable group.

Initial version 2 defaults
Operational: PMP, AI and Risk are mandatory (4 credits); exactly two of the
three remaining modules are required, for exactly 6 credits.
Strategic: PMP, AI and Risk are mandatory (4 credits); exactly two of the
three remaining modules are required, for exactly 6 credits.
Chartered: all four Certified PMO child modules plus AI are mandatory (5 credits);
exactly one of Portfolio/Earned Value is required, for exactly 6 credits.
Certified PMO Professional Level 6 is a group heading and is not double-counted.
Mandatory controls are checked and locked only within the chosen pathway.
Optional controls stop additional choices at the configured count; deselecting
an optional choice makes another available. Mandatory badges and credit totals
remain visible. Inactive pathways' retained choices never count toward the
active pathway's totals.

Validation and persistence
The backend validates mandatory inclusion, module/pathway IDs and membership,
duplicate IDs, pinned published version, maximum optional count and credits.
Mandatory removal, extra options and invalid IDs are rejected on save.
Incomplete valid progress is autosaved as a draft so it survives refresh; that
draft is not a completed module selection. Exact count/target validation is
required for final completion and the server enrolment-submission backstop.
No optional modules are invented automatically for old or new learners.

Publishing validation rejects negative/fractional optional counts, missing
required counts in active version 2 pathways, missing targets, mandatory credits
above target, insufficient optional modules, impossible exact-count credit
combinations, credited/selectable parent headings and mandatory nonselectable
nodes. Exact Decimal arithmetic is used for backend credit feasibility. A
defensive combination-state guard rejects unusually complex administrator
configurations rather than doing unbounded subset work. No fixed module count
limit was added. Zero optional modules is supported, including mandatory-only
paths with optional selection disabled, when credits match the target.

The existing snapshot/version mechanism remains authoritative. Module choices
continue in Extended_ILR.Wizard_draft, and content/rules remain in the assessment's
existing modules_configuration snapshot. No new model or migration is needed.
No historical migration was edited. makemigrations --check found no changes.

Wizard completion
Confirmed PCP stays on Programme Suitability & Modules instead of automatically
advancing past the module choices. The assessment's scoring, confirmation and
programme/account synchronization still run unchanged.
Step 6 is complete only when the assessment is submitted/confirmed, a valid PCP
path/module set exists, and the latest module edit has been successfully saved.
The client tracks the acknowledgement of the latest edit, including quick
deselect/reselect sequences, rather than trusting a temporary checkbox state.
The completion marker is derived and is excluded from persisted wizard answers.

Next, sidebar, direct-route rendering and progress/completeness use the PCP gate.
The server final-submission guard reads saved choices and the pinned configuration,
never a client completion flag. Disabling assessment requirements does not bypass
the module requirement for an already confirmed PCP selection. Previously
submitted/completed enrolment exemptions remain intact.
ME, MM and APM keep their earlier module lists, completion and continuation.

Historical compatibility and rollout
Configuration schema version 1 remains readable. Its original optional-selection
behaviour is retained for pinned historical records; no rules or notes are
silently written into learner snapshots. The earlier default JSON is archived
as modules_legacy_defaults.json for static-era selections pinned as version 0.
New baseline defaults use schema version 2 and contain the requested rules/notes.

For an existing published version 1 configuration, open the existing Step 6
Modules editor and click:
  Apply PCP mandatory-module defaults to draft
Review the settings (including any additional custom pathways) and then use:
  Publish changes
This explicit action populates the original pathways by stable IDs, preserving
module titles, sessions, credits, order and custom notes. Missing targets get the
default target. Custom pathways need their own valid count/target settings.
Existing learner snapshots retain their original version; newly applicable module
enrolments get the newly published version. The agent did not publish a live
configuration or rewrite any learner choices for this task.
