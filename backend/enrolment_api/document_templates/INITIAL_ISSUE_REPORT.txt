ROOT CAUSE (verified from code and read-only configuration)
The live configuration check found zero published template versions and zero
admin drafts. That check was database-enforced READ ONLY and read no learner rows.
Issue selected service.applicable()'s unchanged built-in seed, whose content had
no purple designTheme. Its legacyEquivalent flag was true. The existing PDF
entry points therefore selected their retained plain legacy generators.
The purple designDraft() helper applied to editable copies/previews; it did not
set the original issued binding's default theme. This was not a React CSS issue.

FIX / PUBLISHING RULES
service.issuance_reference() now gives only NEW built-in original issuances the
existing purple-reference-v2 design. All eight issuers share bind_issue(), so
no extra PDF theme or document-specific renderer was created. Published template
content, programme-specific applicability and template versions stay authoritative.

For an actual published template, the original Issue action requires the selected
published content to use purple-reference-v2. A published classic/older-purple
version is never silently restyled or republished. Issue returns an explicit
publicationRequired response before creating any document. The exact admin step:
Compliance Documents > select the applicable shared/programme template > Edit >
Document design: Purple -- supplied reference design > Save Draft > Preview saved
draft > confirm the organisational review > Publish new version > retry Issue.
An unpublished purple draft never overrides a published older design.

No publishing action is needed for the currently verified zero-publication
installation: future first-time Issue uses the built-in purple default. No global
template rows were inserted, modified or published automatically. Existing issued
bindings, old plain PDFs and signed versions were not upgraded in place.

ACTUAL ISSUE / ORIGINAL PDF STORAGE
The real Admin Issue buttons send X-Document-Issue-Mode: initial. A shared wrapper
locks the learner and returns the existing active original on a retry instead of
superseding it or creating a duplicate. Legacy explicit server reissue behavior
without that header is retained. Review retries reuse their existing event key.
Commercial review rejection and existing authentication/signing rules remain.

The first response freezes the exact original render payload in the existing
immutable Document_Template_Render_History table. It then returns the issued
snapshot to the existing frontend API clients. persistOriginalPdf() renders that
ACTUAL snapshot through previewPdf() and the existing jsPDF document entry points,
which now select renderManagedDocument() / purpleReferencePainter for the pinned
purple theme. This is not a builder-only preview or a second learner revision.

The client stores the resulting original PDF bytes and SHA-256 in the SAME
immutable render-history table, associated with the existing template issue.
No schema migration, new table, replacement signature store or Azure-blob rewrite
was needed. The artifact endpoint is learner-scoped, uses CSRF protection for
writes, requires staff to upload, verifies the exact issued snapshot, validates
PDF encoding/header/EOF and length, and refuses replacement. Stored originals
remain immutable, including on retries and after signatures are subsequently made.
A delayed upload must match the original frozen unsigned snapshot, not altered
or signed content. Old documents without the new opt-in metadata are excluded.

Unsigned Compliance Download buttons use the exact stored original bytes. Signed
and historical downloads retain their existing rendering/signature behavior.
Review originals are also stored and accessible through the scoped artifact
endpoint; the normal later Review PDF continues to include subsequently completed
answers and actual signatures through its existing workflow. Issuing does NOT
mark a review as started just to generate its initial PDF. A failed review PDF
upload exposes Retry issuing document, reusing the original rather than duplicating
it. A new original remains Version 1 / R1 in the existing source/issue convention;
no R2 is created just to change its design.
