KBC / DfE EDITABLE DOCUMENT CANVAS — 9 November 2026
Branch: compliance-documents. Existing uncommitted work retained.

Root cause
----------
The PDF uses brandedPurpleTheme / brandedPurplePdf and a frozen presentationTheme
on issued/revision snapshots. FullPageEditor instead only used the older
purple-reference-v2 CSS: reference waves, vertical heading accents and lavender
table headers. It did not render the two logos or the branded footer. The same
design selector therefore led to visibly different browser and PDF presentations.
Site-wide dashboard table rules also imposed their own header colours/shadows.

Implementation
--------------
FullPageEditor remains the existing editable document component. Its contentEditable
surface, page model, safe parser, protected bindings, configuration dialogs and
formatting/page controls were retained. No PDF iframe replaces editable content.
The navigation's React key now includes its position: moving the synthetic first
page previously produced duplicate first-page render keys. Stored page/block IDs
and the existing page serialization are unchanged.

BrandedEditorPage supplies non-editable page furniture OUTSIDE contentEditable:
  - Both actual PNG assets from brandingAssets.json, the same embedded bytes used
    by the PDF renderer; no filesystem URLs, screenshots or substituted artwork.
  - Current deep-purple KBC variant, with original gold/white/transparency intact.
  - Original DfE asset and original colours, without filters or recolouring.
  - headerLogoGeometry / PDF_HEADER: same visible 18 mm height and 16 mm top on
    every current editor page, preserving original image proportions/padding.
  - Shared BRAND_WAVES as top/bottom SVG paths, using their exact PDF coordinates,
    layering and colours. SVG view boxes use the same A4 millimetre coordinate space.
  - The PDF's footer line geometry and purple Page N of T badge.
Furniture is pointer-events:none and cannot intercept cell selection or typing.

brandedEditorTheme reuses BRANDED_PURPLE and PDF_HEADER for CSS variables, fonts,
colours, padding and content clearance. Section icons use the PDF's same section
categories and white glyph shapes. Presentation-only data attributes/CSS SVG
backgrounds decorate headings and signature headings without adding textual
children or changing saved question/block structures.

documentTheme.css adds a scoped branded layer:
  - Current title colour/size and 34 x 1.7 mm purple underline.
  - Rounded lavender section bands, purple icon blocks and white icons.
  - Dark-purple #642783 table headers, white bold text, white body cells and thin
    light-purple borders. Dashboard table colours, corners and shadows are neutralised
    ONLY inside the branded editable paper. New header cells inserted by Add column
    are styled even when the browser represents them as thead td rather than th.
  - Existing explicit text formatting overrides remain supported.
  - A4 paper stays 210 x 297 mm. Current header reserves at least 42 mm, with the
    existing PDF bottom clearance. Long content scrolls within the editable body;
    logos/footer remain fixed and content stays accessible, without being hidden
    behind decorative overlays. Overflow is detected and explained in the UI.
  - Configured margins remain separate from effective header clearance: rendering
    42 mm top clearance does NOT save an invalid 42 mm configured margin. Existing
    settings limits and stored page layouts remain unchanged.

Selector, defaults and persistence
---------------------------------
The visible option is now "KBC & DfE — Purple Branded Design".
Its existing stored identifier purple-reference-v2 remains unchanged; no schema
or identifier migration is needed. Lavender-v1 and classic options remain available.
Global Builder continues preparing an unpublished editable draft through the
existing designDraft path and uses the shared branded canvas for the purple option.

LearnerRevisionEditor passes the saved presentationTheme to both the canvas and
selector. A current branded snapshot with no explicit content design ID displays
the current purple selection/design without rewriting that missing ID on load.
Save/reopen therefore uses persisted snapshot metadata, not a transient toggle.
Snapshots without a branded presentation retain their saved legacy treatment;
v3 branded drafts retain their original logo assets/first-versus-later geometry.
Current v4 presentations use the agreed consistent medium header on every page.

Create still loads the applicable published content and current learner data;
manual answers/new signatures remain subject to existing logic. Edit still loads
the selected revision's content and historical signature references. There are no
changes to source selection, publishing, signing, notifications, history storage,
database bindings, document/PDF generation or issued/signed snapshot retrieval.

Boundaries / limitations
------------------------
This is a visually faithful editable HTML canvas, not a second PDF layout engine.
Browser font metrics, automatic table widths and wrapping can differ from jsPDF.
Binding chips remain visibly identifiable and editable through existing controls;
the PDF renders their actual values. Protected system-linked blocks retain their
existing configuration dialogs rather than becoming freely rebindable HTML.

Badges count EXPLICIT EDITOR pages. Automatic print overflow adds PDF pages:
the test Agreement has 2 editor pages / 4 printed pages and ILR has 1 / 5. The UI
explains this and keeps PDF Preview authoritative. Scroll or insert existing
explicit page breaks to access/split long content; no contractual text was removed
to force a visual pagination match. Existing signed/issued PDFs are not regenerated.
