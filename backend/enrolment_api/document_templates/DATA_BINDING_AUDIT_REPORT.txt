Document data-binding audit — 5 November 2026

Result and scope
Audited the eight repository document templates, all 288 registered placeholders,
native/repeating answer fields, signatory images/status/positions and conditional
signature requirements: 445 logical bindings in total. Repeating items count by
binding path, not by the number of learner records or PDF rows. Of these, 325
were verified, 68 affected paths were corrected and verified, 45 have no canonical
producer in the current document derivations, and 7 source-backed paths were
deliberately empty in the isolated A/B fixtures. These are NOT population counts
for real learners. '68 corrected paths' does not mean 68 independent defects.

Current published template and draft configuration was read under a PostgreSQL
SET TRANSACTION READ ONLY transaction: zero published versions and zero drafts.
The currently connected database therefore adds no configured field bindings to
the eight built-in templates. No production learner rows were read or modified.

Confirmed defects corrected
1. Extended ILR residency: the wizard saves eligibility.residentPrev3Years,
   whereas the retained ILR PDF and template identifier use
   eligibility.residentPrevious3Years. Resolve the alias into new document
   snapshots and field_values, preserving the existing template identifier and
   original ExtendedIlr.answers. Explicit False remains False.
2. Decimal duration: _weeks_between returns Decimal, but scalar discarded Decimal
   values, so real-data template preview could show a blank duration. Decimal
   now serialises as its exact string; no duration calculation was changed.
3. Learning Plan selection: the previous document selectors treated [] like an
   unsaved plan and reinstated the group preset. They also dropped saved modules
   outside the learner's programme catalogue. The new read-only helper reuses
   effective_training_plan, live module-by-id resolution and existing orphan
   fallback. Explicit empty/explicit module scopes remain explicit; inherited
   group assignments and permitted cross-programme modules remain supported.
   Aptem subject fallback retains the existing learning-plan contract. No plan
   or programme assignment is written while a document is derived.
4. Missing programme level: Training/Written Agreement emitted an empty level
   despite curriculum.programmes.level existing. Resolve the officially assigned
   programme by existing placement id, else unique name. Never read an unconfirmed
   recommendation. All four supported assigned programmes are tested.
5. Missing employment fields: Training/Written job title and Training employment
   start date now use WizardIlrLearnerDetails.job_title/employment_start_date for
   this learner. Other employment facts with no proven source remain blank.
6. Written Agreement employer postcode: resolve Employer.post_code through
   EnrolmentUser.employer_id when the linked employer supplies the printed
   address. Extended ILR postcode/address remain fallbacks without that address.
   A deliberately different wizard postcode in the tests proves that the printed
   employer address and postcode do not get mixed.
7. ILR ULN/address fallback and assessed attainment: retain the existing assessed
   RPL priority, selecting the newest detail tied to this learner and a
   non-cancelled review. ULN falls back to this learner's WizardPlr.uln. Personal
   address falls back to WizardPersonalDetails.address only if the learner record
   has no address. No personal data is inferred from another learner or employer.
8. Next-of-kin inherited address: when sameAddressAsLearner=True, derive the
   current learner address/postcode into the new document snapshot instead of
   printing an empty or stale independent kin address. Stored wizard answers are
   deep-copied and never rewritten.
9. RPL PDF lost qualification records: _plr_context already returned WizardPlr
   and WizardPlrRecord data, but buildRows inspected only reviewer answers.
   New binding snapshots print the actual ULN and qualification records, including
   zero credits, even without a reviewer note. Existing reviewed attainment and
   subject-level answers remain present.
10. New review PDFs format saved booleans and multiple choices readably. Unknown
    yes/no strings no longer silently become No in new binding snapshots. Null,
    explicit No/False and numerical zero remain distinct. Literal learner text
    resembling a placeholder is not recursively evaluated.
11. Review score presentation assumed /8 although the current saved scale can
    contain 9. New review documents print the actual saved numeric score without
    inventing a denominator. Skills Radar storage, questions, scoring and UI were
    not changed; historical render envelopes retain the old presentation.
12. Real learner preview excludes cancelled review rows when finding the latest
    applicable review, rather than selecting a cancelled answer set.

Current user-confirmed date rule (supersedes the earlier cohort fallback)
For NEW learner-specific documents, learner_start_date and learner_end_date are
the ONLY apprenticeship/training period dates. A missing date stays blank and
produces a warning; programme Start_date/End_date and cohort dates are not used
as substitutes. These rules are shared by new AA/Training/Written derivation,
common date placeholders and newly pinned review header fields. Read-only
review headers outside this new-document path keep their earlier behaviour.

No date column is updated. A non-empty invalid learner date stays unresolved;
it is not quietly replaced by a cohort date. Missing dates and reversed periods
produce bindingWarnings; the Admin PDF Preview displays these warnings. The
existing duration calculation returns no duration for reversed periods. No
guessed date or duration is introduced. These warnings do not create a new
signing/admissions approval workflow. Review appointment dates and sign dates
are not changed. Missing dates despite populated cohort dates, one-sided missing dates, invalid date and conflict
cases are covered by isolated tests.

Suspicious 02/02/1900 date
No document derivation uses that date as a fallback. A test saves 1900-02-02 in
WizardIlrLearnerDetails.employment_start_date and proves the document preserves
that exact source value. An actual occurrence must be checked against that
learner's saved column or issued snapshot; it must not be 'corrected' based on
appearance alone. This audit did not inspect or edit a real learner's date.

Programme and PCP conclusions
Programme titles come from the officially assigned EnrolmentUser.programme, not
Assessment.result. programme_assignment.py synchronises a confirmed alternative
selection into that record and its profile; an authorised later placement change
remains authoritative. Catalogue level lookup follows the existing placement id.
No programme/cohort/assessment selection logic was changed.

All three PCP paths (operational, strategic, chartered) are tested to ensure that
reading a Training Plan does not silently replace the actual assigned learning
plan. However, Assessment.modules_selection stores suitability-module identifiers
which have no declared relationship to curriculum.modules.module_catalogue_id.
The operational Learning Plan is the existing document source. Automatically
turning a PCP pathway choice into taught curriculum modules requires a defined
ID mapping; matching module titles or treating credits as OTJ hours would be
invented business logic. This integration remains unresolved and was not changed.

OTJ calculations and presentation
AA planned hours, Training programme/OTJ total and Written total keep the existing
sum of selected module total_otjh rounded to two decimal places. Component hours
come from curriculum.components.expected_otjh. No weights, hour sources or
rounding formula were changed. The repaired selector changes which actually
assigned modules reach the existing calculation, fixing dropped/reinstated rows.
Module planned dates now use authored module start_date when present, with the
existing learner-start fallback. Methods use the actual component type mapping.

Training Plan keeps decimals such as 0.75, 2.5, 0.15 and 0 as intact values in
the existing repaired purple table. Written Agreement intentionally keeps its
established formatHoursMinutes presentation: 0.75 -> 45m, 2.5 -> 2h 30m,
0.15 -> 9m, 0 -> 0h, 3.4 -> 3h 24m. The underlying hours are unchanged.

The Learning Plan modal additionally counts eligible review-meeting hours in its
combined total. The user clarification answered the date question in both reply
slots, so no decision to change this document calculation was received. Existing
module-only totals remain; whether contracts should include the meeting subtotal
is still a business-rule question, not a value to infer during a binding fix.

Document lifecycle and history protection
New render envelopes carry bindingVersion=2, stored inside the existing issued
template JSON. There is no model field or migration. with_template uses the
original stored envelope for an issued document. Old envelopes without the flag
retain version-1 rendering behaviour; pre-builder records are explicitly version
1. New review first-signature snapshots preserve the existing header/answer
freeze rules. A learner-specific draft starts from the source's frozen data,
template version and original signature provenance, not current live derivation.
Finalised copies remain immutable under the existing workflow. No stored PDF,
template version, signature, evidence file or production learner record changed.
