ADMIN DOCUMENT PREVIEW — IMPLEMENTATION AND VERIFICATION
Date: 9 November 2026
Branch: compliance-documents

RESULT
The four Compliance and four Review document rows on the admin learner profile
now have a reusable Preview action, both before first issuance and after issue.
Opening/closing Preview never issues, signs, finalises, creates a revision, opens
the editor, starts a review, or sends a signature notification.

VIEWER
Extended the existing DocumentPreview and existing accessible users-page Modal.
The browser PDF viewer provides all pages, scrolling, zoom and page navigation.
The surrounding modal retains focus trapping, Escape, Close and return focus.
It has a wrapped mobile footer, Download preview PDF and a safe Open in new tab
fallback. Object URLs are revoked on close; unavailable/corrupt stored PDF
responses produce errors rather than silently substituting a different file.
The preview download and embedded viewer use the same blob. Existing row Download
and historical View/Download/Edit/Compare/Create/Delete Draft actions remain.

EXACT SOURCE AND SIGNING SAFETY
GET /enrolment_api/document-templates/learners/<pk>/documents/<key>/preview/
  sourceId=<the existing row's source ID or review event key>
This resolves only that learner's exact currently active issued source. It does
not select a newer global template, an open draft, or the latest learner revision.
Original R1 and its published template version are labelled in the viewer.
Historical/updated copies retain their exact existing History actions.

The response uses the existing source serializers and issued template binding.
Compliance particulars come from the saved issued source, not current profile
data. Signed Reviews require their existing frozen review snapshot. If that is
unavailable, the endpoint fails closed with an explanation instead of filling a
historical signed review from the learner's current data.

Existing immutable original PDF bytes are reused only when the saved artifact
matches the current issued content and signatures. An unsigned original is never
substituted for a partly/fully signed version. Where no matching persisted PDF
artifact exists, the existing download renderer produces a temporary view from
the authoritative saved source/template/signature snapshot. No old stored PDF is
rewritten, restyled, reissued or replaced. Byte identity is verifiable for the
persisted-artifact path; transient legacy rendering has the existing renderer's
normal PDF metadata and is not claimed to reproduce an absent historical file.

Admin Sign as provider/Review Sign first opens this preview. Continue to signature
appears only after the PDF loads, then opens the existing signature capture UI.
POST .../documents/<key>/sign-reviewed/ checks a signed token binding learner,
document key, exact source ID and hash of the complete serialized document.
Tokens expire after one hour. Under the existing database transaction/source-row
lock, changed content/signatures, superseded sources, foreign tokens and missing
tokens are rejected with a request to preview again. The endpoint then delegates
to the existing signer, preserving its validation, permissions, completion checks,
signature dates, audit/archive and enrolment advancement. Review completion is
still required. Signature withdrawal remains the existing signer's operation.
No alternate signature-record system or automatic signature was introduced.

PRE-ISSUE PREVIEW
The same GET endpoint with phase=pre-issue resolves issuance_reference, using the
actual learner and applicable published template/programme variant. Unpublished
drafts are ignored. The existing derivation/binding/rendering functions supply
content and warnings. The default uses the same shared purple first-Issue design.
The viewer clearly says PRE-ISSUE PREVIEW. The preview has no signing token.
If another admin already issued the document, the request asks to reload and use
the issued version instead. The actual Issue operation is unchanged and resolves
its own current approved content at issuance time.

PERMISSIONS / STORAGE
Both endpoints use the established enrolment authentication/access-grant gate,
an additional staff requirement, and existing CSRF protection for writes.
Learner/employer/non-enrolment staff cannot use the admin preview/sign endpoints.
Source lookup includes learner ID, document key and exact source identifier.
Stored PDFs remain behind the existing authenticated learner-scoped endpoint.
No public private-document URL, runtime DDL, migration, new table or live learner
record modification was needed. Tests use explicitly isolated in-memory SQLite.
