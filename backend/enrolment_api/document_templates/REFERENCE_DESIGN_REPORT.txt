Purple reference PDF design implementation — 5 November 2026

Scope and reference
Implemented on the existing compliance-documents branch, preserving all prior
uncommitted work. No commit, push, merge, rebase or branch switch was performed.
The actual supplied file was Individual_Learner_Record_Purple_Design.pdf in the
user's Downloads directory (without the attachment prompt's '(1)' suffix).
All five pages were rendered and inspected before implementation. Each page
contains one raster image; there are no recoverable vector paths or font names.
Only its visual appearance was used. No personal information, wording or
signature image from that reference was imported into templates or assets.

Actual rendering pipeline and prior mismatch
The application uses jsPDF 4.x and jspdf-autotable 5.x, not ReportLab or an HTML
print renderer. The four compliance generators and the shared review generator
dispatch managed templates to renderManagedDocument. PDF preview, downloads,
issuance and learner-specific revision generation already use these paths.
The old lavender-v1 theme was generic: filled heading panels, boxed signatures,
no reference waves, different spacing and automatic Learning Plan columns.
Original published templates deliberately retained their old grey appearance.
Changing an editable draft must not restyle an existing issued version.

New versioned treatment
purple-reference-v2 centralises the reference colours, typography, margins and
vector decoration. Approximate measured colours: heading RGB 47/12/79; accent
143/26/235; table header 231/215/252; border 195/155/228. Title 22pt, section
14pt, body 10pt, table 9.5pt, horizontal margins 12mm. Curved vector waves are
recreated at the upper-right and footer, with a clear reading area. Continuation
content starts below the top waves; footer content remains above the lower ones.
Main titles have the segmented purple/lavender divider; interior section
headings have the vertical accent bar. Tables have white bodies, lavender
headers, thin borders and rounded outer frames. Two-column tables balance
labels against long answers rather than allocating a tiny value column.
Signatures preserve their original images, aspect ratio, role, names, dates and
historical provenance, with a thin lavender line and no heavy enclosing panel.
Compact declaration/signature sequences stay together where they fit.
Builder-added content uses the same theme and retains supported explicit styles.
The editable HTML surface shares the tokens and decoration; PDF Preview is the
authoritative paginated output, since one editable page can flow onto PDF pages.

All eight document types use the same managed painter:
Apprenticeship Agreement; Individual Learner Record; Training Plan; Written
Agreement; Eligibility Review & FS Discussion; RPL and Experience; Workplace
Health & Safety Declaration; ULN Privacy Notice & Learner Acknowledgement.

Training Plan layout
The default A4 portrait reading width is 186mm. Its five columns are explicitly
allocated approximately 76/32/30/26/22mm: Activity, Method, Delivery Lead, Date,
OTJ. Date and OTJ widths expand if their measured values require more room.
Activity keeps the largest share. Text is measured and wrapped at its actual
font size; row height follows line count. Numeric/date body cells never wrap.
Hours use String(originalValue), without rounding, totals or recalculation;
existing string precision such as '0.7500' and '12.50' remains intact.
Modules and weeks have distinct lavender treatments; activities remain white.
Headers repeat at identical widths on continuation pages. Short rows remain
whole; individually oversized rows can continue by complete text lines. Module
and week headings reserve room for associated rows. Explicit page breaks remain.
A narrow configured reading area switches only the Learning Plan to related
field/value rows instead of tiny fonts or making all documents landscape.
Long activities remain table body content, never oversized repeating headers.

Usage and version safety
Open Compliance Documents -> Edit a template -> choose 'Purple — supplied
reference design' -> Save Draft -> Preview saved draft. New editable copies of
original/v1 templates prepare v2 locally; explicit Original layout remains
selectable. Existing published-version Preview intentionally keeps that version's
design. Global publication remains a separate explicit admin action and was NOT
performed. New issuance uses the new style after the existing publication flow.
Learner-specific revisions use their existing version/provenance mechanism.
No database migration, schema alteration, production data update or PDF storage
rewrite was needed. Historical template IDs, issued snapshots, marks, signature
statuses and original files remain unchanged.

Integration notes and limitations
Coordinate changes to render.ts, documentTheme.ts, pageDocument.ts, types.ts,
FullPageEditor.tsx, page.tsx and registry.py with teammates touching this feature.
Keep both theme IDs: lavender-v1 must not be renamed to v2 or historical output
would change. New helpers are dedicated files; unrelated shared components were
not refactored. No dependency or migration coordination is needed.
The source reference is raster-only, so vector curves/colours are reconstructed
and Helvetica provides a compatible font, rather than a recovered original font.
This is a close visual match, not a pixel-for-pixel replica. Explicit admin page
breaks and existing content remain; page count follows real content length.
The existing Latin-text/font support is unchanged. Production drafts/templates
were not saved or published by this task; the admin must review and publish
through the normal application flow before future issued documents use v2.
