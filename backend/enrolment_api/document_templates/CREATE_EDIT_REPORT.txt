Create latest template with current learner data / fresh signatures

CURRENT BEHAVIOUR
Create opens a new independent learner-specific document revision using the
latest published template applicable to the learner's programme. Existing
controlled document derivations fill the learner's current name, programme,
learner-specific start/end dates, employer details, assigned learning plan,
modules, activities, hours and saved document/review data where available.
Missing information stays missing; dates do not fall back to cohort dates.
Missing-field and learner-date warnings remain visible in PDF Preview.

The complete payload, dynamic field values and actual template version are
snapshotted at Create. Preview, Save and Finalise use that snapshot. Changes to
the learner or global template after Create do not silently alter this copy.
An original/signed document is never used as the new document's answer source.
Published contractual wording and configured defaults remain as published.

Create always starts unsigned. Old signature images, signer names, dates,
provenance and fully-signed/completion status are removed from the new copy.
Draft save or preview does not create signing obligations. After Save, review the
PDF and Finalise: content becomes read-only, the revision appears in the learner
Documents area and the existing fresh-signature workflow opens for the required
learner, employer and provider parties for that document type. Actual independent
signatures are required before Signed status is shown. Old versions/signatures
remain unchanged and accessible.

The signing envelope is newly created in the existing document/review models and
contains this new revision's frozen data, including the learning plan. Signed PDF
rendering therefore uses the same data that was reviewed. Pending-signature
metadata displays this revision's actual template version, rather than the
original issue's older version. No duplicate notification/signature tables exist.

Edit still starts from the exact selected historical version. Continue editing
resumes that draft. Keep Existing Signatures and Sign Again remain available for
historical editing, with correct provenance. Existing View/Download/Compare/Delete
and independent History/chevron controls remain available.

COMPATIBILITY
A pristine draft from the previous empty/unanswered Create flow may be initialised
with current learner data on a new Create request. UUID and revision number stay
stable; edit_version increases and the prior request, actor and time are audited.
Only edit_version 1 drafts without saved reasons, content edits or signature
evidence qualify. Saved work is never replaced automatically.

The existing one-open-draft constraint, request UUID idempotency, source/issue
transaction locks and MAX(number)+1 allocation (including deleted draft numbers)
remain. No migrations, schema changes or live database updates were performed.
All ordinary document writes occur only when the admin uses the authorised UI.
